# State

How a service keeps its Postgres and Redis state. Read alongside [SKILL.md](SKILL.md) before you add a table, a column, a query or a Redis key.

## One store package

- One package owns every table and every Redis key that holds a model's state. No other package imports the ORM, writes SQL or keeps model state in Redis. Nothing outside it holds a `*bun.DB`.
- A model is a Go struct for one table (or one Redis key family), in a file named after it in the singular: `Session` in `session.go`. The file holds the model, its `Validate() error`, its errors (`ErrNoSession`), the repository named in the plural (`Sessions`) and its methods.
- Repositories are fields of one `Store`, so a caller writes `store.Sessions.Get(ctx, customerID, id)`.

## Verbs

The tenant comes first after `ctx` for every tenant-scoped model.

| Method | Does |
| --- | --- |
| `Get(ctx, customerID, id)` | One row by primary key; `ErrNoX` when absent. Other lookups are `GetByName`, `GetByEmail`. |
| `Select(ctx, customerID, filter)` | A page of rows, filtered by an `XFilter` struct with `Limit` and a cursor. |
| `Insert(ctx, *X)` | A new row. Fills id and timestamps on the model. |
| `Update(ctx, *X)` | Replaces the mutable columns; `ErrNoX` when no row matched. |
| `Upsert(ctx, *X)` | Insert or update on the natural key. |
| `Delete(ctx, customerID, id)` | Removes one row; `ErrNoX` when absent. |

A state change that is more than a column write gets a domain verb: `Calls.Finish`, `Contacts.Lease`. Batch versions take a slice (`InsertMany`, `GetMany`) and run one statement, never a loop of single ones.

## Errors at the boundary

- Translate driver errors into the store's own: `sql.ErrNoRows` becomes `ErrNoX`, a unique violation (matched by its Postgres code on `*pgconn.PgError`, never by text) becomes `ErrXExists`. Callers match these with `errors.Is`; nothing above the store knows the driver.
- Wrap everything else with the operation, `store: save session: %w`, and let it travel up as an internal failure. A failed query is never reported as "not found".
- Check `rows.Err()` after iteration, check `Commit`, and defer `Rollback` (it is a no-op after a commit).

## Validation

- Every model has `Validate() error`. It checks what the table's NOT NULL and CHECK constraints check, plus what the column means (an E.164 number, a known enum value, a positive limit), and returns a `*ValidationError` naming the field.
- `Insert`, `Update` and `Upsert` call `Validate` before they touch the database, so invalid data never reaches Postgres. The API answers a `*ValidationError` with a 400 and its text: it is the one store error written for the caller.
- Keep the database constraints as well: they guard writers outside the store (migrations, a psql session).

## Queries

- Use the ORM's builders; raw SQL only for what they cannot express.
- Every method has a query budget, asserted in its test by counting queries: a Get is one query, a Select one (two with a count), an Insert one. A method that reads related rows joins or batches them; it never queries once per row (N+1).
- Every Select and Get filters on columns an index covers, tenant first. A new query on a large table gets an `EXPLAIN` check in a test: no sequential scan on seeded data.
- Add a column to the table that owns it, nullable or with a default, so the previous release still reads the row. Do not create a 1:1 side table to dodge a rollback.
- A table of work that instances claim (jobs, deliveries) leases due rows with `FOR UPDATE SKIP LOCKED` in one query, and every write after the claim checks the lease holder, so a claim whose lease ran out cannot overwrite the next one. Write that once and reuse it.

## Redis

- Redis state that belongs to a model (a cached row, a call's events, a last-seen time) is a repository too, in the model's file.
- A method touching more than one key sends one round trip: `DoMulti`, a `MULTI`, or a Lua script. A loop issuing one command per item is a bug.
- Every key has a TTL or a named owner that deletes it. Name keys `<family>:{<tenant>}:...` so a tenant's keys share a cluster slot when a script needs several.
- A cache has an invalidation path and is keyed by tenant. Rate limiters, counters and pub/sub are protocols, not model state: they live in their own packages, under the same one-round-trip rule.

## Migrations

- Migrations are files under goose, one change each, never edited after release. A table never moves between databases in place: add it to the new one, copy, then drop it.
- Keep a schema dump of what the migrations leave, regenerated by a command, and a test that fails while it is stale.

## Tests

- Store tests run against a real Postgres and Redis, one database per test run. Test behavior, the other tenant's rows staying invisible, `Validate` refusing bad rows, and the query budget. See [testing/store.md](testing/store.md).
